18个恶意npm软件包供应链攻击

攻击者利用npm生态投递跨平台RAT恶意程序

Software Supply Chain Attack
攻击平台： npm Registry

攻击类型： 供应链攻击 / 恶意依赖

恶意载荷： Cross-platform RAT

影响对象： JavaScript开发人员、开发环境

事件概述

攻击者向 npm 仓库发布多个恶意软件包， 通过名称伪装、依赖混淆等方式诱导开发者安装。

当用户执行：

npm install package-name

恶意生命周期脚本自动执行， 随后下载并运行远程访问木马。

攻击链分析

攻击者创建恶意npm包
→
伪装合法开发工具
→
诱导开发者安装
→
执行install脚本
→
部署RAT

恶意执行流程

开发者执行 npm install
↓
preinstall / postinstall脚本执行
↓
下载恶意Payload
↓
建立C2通信
↓
攻击者远程控制设备

RAT攻击能力

系统信息收集 → 远程命令执行 → 文件访问 → 开发环境信息窃取 → 持续控制

影响分析

攻击目标 开发人员工作站
影响系统 Windows / macOS / Linux
主要风险 代码泄露、凭证窃取、远程控制
攻击场景 软件供应链污染

为什么npm供应链危险？

开发者通常默认信任：

npm包 → 第三方依赖 → 自动安装脚本

攻击者利用这种信任关系， 可以一次影响大量开发环境。

检测建议

✅ 审查package.json依赖变化

✅ 检查异常postinstall脚本

✅ 使用npm audit扫描依赖

✅ 固定依赖版本(package-lock)

✅ 监控Node.js异常网络连接

企业防护建议

→

→
CI/CD安全检测
→
