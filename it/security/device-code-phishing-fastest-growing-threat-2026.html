Device Code Phishing成为2026年增长最快威胁

利用OAuth授权流程窃取身份Token的新型钓鱼攻击

Identity Security
来源： The Hacker News

攻击类型： 身份认证攻击 / OAuth滥用

主要目标： Microsoft 365企业账户

核心技术： OAuth 2.0 Device Authorization Grant

什么是Device Code Phishing？

Device Code Phishing是一种利用合法身份认证流程的新型钓鱼攻击。

攻击者并不需要伪造登录页面，也不一定需要获取用户密码， 而是诱导用户完成真实认证流程，从而授权攻击者获得访问Token。

攻击链分析

攻击者申请Device Code
→
发送钓鱼诱导
→
用户输入验证码
→
生成OAuth Token
→
账户被接管

技术流程

攻击者启动OAuth设备认证
↓
获取合法Device Code
↓
诱导用户访问登录页面
↓
用户输入攻击者提供代码
↓
攻击者获得Access Token

为什么攻击成功率高？

1 使用真实身份认证页面，降低用户警惕
2 无需窃取密码
3 可以绕过传统MFA防护
4 攻击者获得合法Session Token
5 适合自动化大规模攻击
6 可用于企业账户横向移动

攻击者获得权限后

OAuth Token → 访问Microsoft 365 → 读取邮件 → 访问OneDrive → 窃取企业数据 → 进一步攻击内部系统

传统钓鱼 VS Device Code Phishing

传统钓鱼 伪造登录页面窃取账号密码
Device Code Phishing 利用合法OAuth流程获取Token
防御难度 更高，因为使用真实认证服务

安全风险

可能导致：

❌ Microsoft 365账户接管
❌ 企业邮件泄露
❌ 云资源访问
❌ BEC商业邮件诈骗
❌ 内网横向移动

企业防护建议

✅ 限制不必要的Device Code Flow

✅ 启用Conditional Access策略

✅ 监控异常OAuth授权

✅ 定期审查第三方应用权限

✅ 加强员工身份安全培训

未来趋势

传统攻击：
密码窃取 → 账户登录

新型攻击：
OAuth授权滥用 → Token窃取 → 身份控制
