vBulletin再爆预认证RCE漏洞：无需登录即可接管论坛服务器
发布日期：2026-07-27
CVE-2026-61511 CVSS 9.3 Critical

全球数百万网站使用的论坛软件 vBulletin， 近日被曝出一个严重安全漏洞。 攻击者无需任何账号，仅需发送一个精心构造的 HTTP 请求， 即可在服务器上执行任意代码，完全控制目标网站。

漏洞概述

2026年7月27日，安全研究人员 Egidio Romano （昵称 EgiX）公开披露 vBulletin 中的一个 预认证远程代码执行漏洞。

漏洞编号： CVE-2026-61511

漏洞类型： Pre-Auth Remote Code Execution

CVSS v4： 9.3（严重）

攻击者无需身份验证，也不需要用户交互， 只需向公开的 vBulletin 站点发送特制 HTTP 请求， 即可利用漏洞执行 PHP 代码。

漏洞原理

问题位置

漏洞存在于 vBulletin 模板引擎： 

/includes/vb5/template/runtime.php

vB5_Template_Runtime::runMaths()

该函数原本用于处理模板中的数学表达式： 

{vb:math 2+2}

但由于开发者直接将用户输入传入 PHP eval() 函数执行，导致攻击者能够注入任意代码。

过滤机制绕过

开发者增加了正则过滤： 

$str = preg_replace(
'#([^+\-*=/\(\)\d\^<>&|\.]*)#',
'',
$str
);

但是过滤策略存在缺陷。 攻击者利用 PHPFuck 技术， 通过允许的字符组合生成任意 PHP 表达式。

由于过滤允许 XOR 运算符： 

^

攻击者可以构造恶意字符串， 最终绕过限制进入 eval() 执行。

        ↓

受影响版本

版本 影响范围 修复版本
vBulletin 5.x 5.0.0 - 5.7.5 -

漏洞危害

  • 无需账号即可攻击
  • 无需用户点击
  • 可执行任意PHP代码
  • 可窃取用户数据库
  • 可植入后门维持访问
  • 可将网站作为攻击跳板

企业及站长处置建议

立即行动：
  • 检查当前 vBulletin 版本
  • 升级至 vBulletin 6.2.2
  • 限制 ajax/render 外部访问
  • 检查异常 HTTP 请求日志
  • 备份网站和数据库

核心启示

  • 任何用户输入进入 eval() 都属于高危设计。
  • 黑名单过滤无法替代安全编码。
  • PoC公开后攻击窗口会快速缩短。
  • 公开服务必须持续关注安全更新。
